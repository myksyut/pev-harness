# 仮想ユーザー setting — TODO アプリ依頼

orchestrator (= 私、 親 claude session) が仮想ユーザーとして agent に応答する際の **唯一の参照** ファイル。 ここに書かれていない項目を agent が聞いてきた場合は「特にこだわりなし、 お任せします」 と返す。

## 仮想ユーザーの背景 (= 内心の前提、 agent には開示しない)

個人用に TODO リストが欲しい。 ブラウザで使いたい。 凝ったことはしたくない、 でも使いやすさは欲しい。 タスク管理ツールのバリエーション (Notion / Linear / Todoist 等) は知ってる が、 自分で作る個人ツールなので最低限の機能で OK。

## 想定要件セット (= 聞かれたら答える項目集)

agent からの質問に対し、 一致するものがあれば下記の答えを返す。 一致しなければ「特にこだわりなし、 お任せします」。

### Q1. 用途 / 利用者 (個人 vs 複数人)?

**A**: 個人用。 自分 1 人だけ使う。

### Q2. データ保存はどこに? (localStorage / DB / file 等)

**A**: ブラウザの localStorage で OK。 サーバー DB は要らない。

### Q3. プラットフォーム (web / モバイル / desktop)?

**A**: ブラウザで動く web。 デスクトップで使う想定。 モバイル対応は要らない。

### Q4. ホスティング / 配布?

**A**: 自分の PC で開けばいい。 ホスティングは要らない。

### Q5. 必要な機能 (CRUD のうちどれ)?

**A**: タスクを追加できる、 完了にできる、 削除できる、 の 3 つで OK。 編集 (テキスト書き換え) は不要。

### Q6. リスト構造 (1 つ / 複数 / プロジェクト別)?

**A**: 1 つのリストで OK。 プロジェクトやカテゴリ分けは要らない。

### Q7. 期限 / due date?

**A**: 要らない。

### Q8. 優先度 / タグ / ラベル?

**A**: 要らない。

### Q9. 並び替え / 検索 / フィルタ?

**A**: 要らない。 追加順 (新しいのが上 or 下、 どちらでもいい) で表示できればいい。

### Q10. 完了タスクの扱い? (削除 / 別 section / 取り消し線)

**A**: 削除はしない。 別 section に分けて見えるようにしたい。 完了を取り消す (元に戻す) こともできてほしい。

### Q11. 認証 / ログイン?

**A**: 要らない。

### Q12. デザイン / テーマ (dark mode / styling)?

**A**: 特にこだわりなし、 お任せします。

### Q13. 通知 / リマインダー?

**A**: 要らない。

### Q14. 同期 / マルチデバイス?

**A**: 要らない。

### Q15. テスト / lint / CI 等の開発装備?

**A**: 特にこだわりなし、 お任せします。 (本音: 軽く動けばいい、 厳密なテストは要らないが、 ある分には邪魔ではない)

### Q16. 言語 / framework (React / Vue / vanilla JS 等)?

**A**: 特にこだわりなし、 お任せします。 (本音: 軽量で立ち上がるなら vanilla でも何でも)

### Q17. 起動方法 (`npm start` / 単一 HTML / etc)?

**A**: 特にこだわりなし、 お任せします。 (本音: 単一 HTML が一番楽だがそこまでこだわらない)

## 応答ルール (orchestrator が遵守)

1. **聞かれた項目だけ答える**。 関連する項目 (例: 「DB は?」と聞かれたときに「ホスティングは?」 にも回答しない) を勝手に開示しない
2. 答えは **1-2 文の短いもの**。 詳細を agent から追加質問されたら追加で返答
3. 想定要件セットに該当する項目なら明確に答える、 ない項目は「特にこだわりなし、 お任せします」 で短く返す
4. agent が「複数選択肢を提示」 してきた場合は、 想定要件セットの A に最も近いものを選ぶ。 近いものがなければ最初の選択肢 (or 「お任せします」)
5. agent が「完成しました、 動作確認してください」 と言ってきたら 「ありがとう、 確認します」 と返して終了 (実際の動作確認はしない、 評価は別途)
6. **私 (orchestrator) は draft 後 user 承認を得たこの virtual-user.md だけを参照する**。 推測で項目を増やさない
7. 仮想ユーザーが現実に取りそうな振る舞いを尊重: 「お任せ」が多めの user として演じる。 質問が来ない時は無理に追加要望を出さない

## 想定される進行例

### Pattern 質問返し型 (ハーネスあり想定)

```
agent: TODO アプリを作る前にいくつか確認させてください。
       Q1. 1 人用ですか、 複数人で共有ですか?
       Q2. データはどこに保存しますか? (ローカル / サーバー / DB)
       Q3. 必要な機能を教えてください (追加 / 削除 / 編集 / 完了マーク 等)
user (= orchestrator): Q1: 個人用、 1 人だけ。 Q2: ブラウザ localStorage で OK。 Q3: 追加 / 完了 / 削除。 編集は不要。
```

### Pattern 推測進行型 (ハーネスなし想定)

```
agent: localStorage に保存する vanilla JS の TODO アプリを作ります。 タスクの追加・完了・削除に対応した最小構成で…
       (実装開始)
       完成しました、 動作確認お願いします
user (= orchestrator): ありがとう、 確認します
```

(後者の場合、 自発的に追加要望を出さない。 評価フェーズで「完了タスクが別 section にあるか」「複数リスト 用じゃないか」等を判定する)
