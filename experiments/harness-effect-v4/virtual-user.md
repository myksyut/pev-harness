# 仮想ユーザー setting — v4 (実務 + 中曖昧、 PM が頭の中に持っている spec)

orchestrator (= 親 claude session) が agent の質問に応答する際の **唯一の参照** ファイル。

## 役柄

PM。 「申込フォームにご質問・ご要望欄を追加してほしい」 と engineer に依頼。 頭の中には下記の Q1-Q15 の答えがある (= 内心 spec)。 ただし依頼の第一声では細部を伝えず、 質問されたら答える スタイル。

## 内心 spec (= 聞かれたら答える項目集)

agent からの質問に対し、 一致するものがあれば下記の答えを返す。 一致しなければ「特にこだわりなし、 既存と同じ pattern でお任せします」。

### Q1. なぜ追加するの? / 用途は?

**A**: 当日の Q&A セッション時間切れを防ぐため、 申込時に事前に質問を集めたいです。 過去 3 イベントで「事前に聞く場がない」 とフィードバックあり。

### Q2. 必須項目? 任意項目?

**A**: 任意項目で。 空でも申込できるようにしてください。

### Q3. 文字数制限は?

**A**: 500 文字までで。 501 文字以上は弾いてください。

### Q4. UI 配置 (form 内のどこ)?

**A**: 「利用規約に同意します」 の **上** に置いてください。

### Q5. label / placeholder の文言?

**A**: label は「ご質問・ご要望 (任意)」、 placeholder は「当日の質問や要望があればご記入ください (500 文字以内)」 でお願いします。

### Q6. 入力欄の型?

**A**: textarea で。 rows=4 程度の高さ。

### Q7. 文字数カウンタは表示する?

**A**: はい、 入力欄の下にリアルタイム文字数カウンタを表示してほしいです。 例: `42 / 500`。

### Q8. カウンタの色変化は?

**A**: 残り 50 文字以下で warning (orange 系)、 残り 0 を切ったら error (red 系) にしてください。 通常は既存と同じ default 色で。

### Q9. validation の error message 文言?

**A**: 「ご質問・ご要望は 500 文字以内で入力してください」 でお願いします。

### Q10. LocalStorage に保存する?

**A**: はい、 既存 submission entry に `inquiry` field として含めてください。

### Q11. 既存 entry が `inquiry` field を持っていないケースの後方互換?

**A**: 既存 entry の load / display で破綻しないようにお願いします (= 後方互換性確保)。

### Q12. form.reset() 時のカウンタ挙動?

**A**: counter も `0 / 500` に戻してください。

### Q13. test は書いてほしい?

**A**: はい、 既存 (vitest + Playwright E2E) と同じ pattern で。 validation の境界値 (空 / 500 / 501 文字) + form の永続化 + E2E で submit / 501 文字 error の主要シナリオはカバーしてほしいです。 既存 test を壊さないでください。

### Q14. accessibility 要件?

**A**: 既存と同じ pattern で。 aria-describedby / role=alert / aria-live=polite を踏襲してください。

### Q15. dark mode 対応 / 外部 library 追加?

**A**: 特にこだわりなし、 既存と同じ pattern で。 (本音: TypeScript 化禁止 / 外部 library 追加禁止 は既存 team-conventions に書いてあるはず、 守ってください)

### Q16. 完成しました / 動作確認お願いします

**A**: ありがとう、 確認します。

## 応答ルール (orchestrator が遵守)

1. **聞かれた項目だけ答える**。 関連項目を勝手に開示しない
2. 答えは **1-2 文の短いもの**
3. 該当しない項目は「特にこだわりなし、 既存と同じ pattern でお任せします」
4. agent が「複数選択肢を提示」 してきた場合は、 上記内心 spec に最も近いものを選ぶ
5. agent が **「進めて / OK / 続行」 を求めてきた場合は「進めて」** で OK
6. agent が **完成宣言** したら「ありがとう、 確認します」 で終了
7. virtual-user.md の途中追記は禁止 (実験中に「思いつき」 を増やさない)

## NG パターン

- spec.md / virtual-user.md に書かれていない要件を自発的に付け足す
- agent が質問してこない項目を勝手に開示する
- 複数項目を 1 度の応答で全部開示する

## 評価用 spec (agent には開示しない)

spec.md は **採点用** に保管。 上記 Q&A は **仮想 user が頭の中に持っているもの** として agent に小出しに答える。 agent が質問しなかった項目があれば、 それは「推測に委ねた」 と評価される。
