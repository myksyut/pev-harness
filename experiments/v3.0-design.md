# v3.0 設計 — Plan on-demand + 質問返し強化 (= 「user の頭の中の spec を引き出す」 ハーネス)

**Status**: Design draft (user-approved axes 反映済)
**Predecessor**: v2.1.6 (released)
**Reference**: [RFC-v3.0.md](RFC-v3.0.md) + harness-effect-v1/v2/v3/v4 実験データ

## 0. 大方針 (user 確認済 axes)

- **Axis 1 (value)**: ハーネスの主要 value = 「**質問返しで user の頭の中の spec を引き出す**」 (v3 で証明済)
- **Axis 2 (channel)**: Plan agent の **中に** 質問判定ロジックを強化 (= Phase は増やさない、 既存 Plan を改良)
- **Axis 3 (3-phase)**: Plan を **on-demand** に (= 必要な時だけ起動、 default は Execute → Verify の 2-phase)

## 1. 新しい flow

```
┌──────────────┐
│  User input  │
└──────┬───────┘
       │
       ▼
┌──────────────────┐
│   Triage (新規)  │  軽量 router (1 turn 以内)
│   - context 検知 │   ├─ cwd に既存 codebase あり?
│   - 曖昧度 評価  │   ├─ spec doc / Linear Issue あり?
│                  │   └─ task complexity 推定
└──────┬───────────┘
       │
       ├── 「明確 + 既存 pattern あり」 ──► Plan skip
       │                                    │
       │                                    ▼
       │                                  Execute → Verify
       │
       └── 「曖昧 / zero context」 ────► Plan invoke
                                            │
                                            ▼
                                          Plan
                                            │ (質問返し必須、 spec 引き出し)
                                            ▼
                                          Execute → Verify
```

### Phase 別の役割 (v2.x から変わる点)

| Phase | v2.x | v3.0 |
|---|---|---|
| (新規) Triage | なし | 軽量 router、 Plan 必要性判定 |
| Plan | 常時起動 | **on-demand**。 起動した時は質問返し強化 |
| Execute | plan.md 必須 | plan.md があれば優先、 なければ user prompt + cwd context から直接実装 |
| Verify | 常時起動 | 不変 (audit artifact 維持) |

## 2. 主要変更点 (file 単位)

### 2.1 新規: `agents/triage.md`

- model: sonnet (軽量で十分)
- effort: low
- 役割: 1 turn 以内で「Plan が必要か」 を判定
- 出力: `artifacts/triage.json` (single decision + reason)

```json
{
  "decision": "plan_required" | "plan_skip",
  "reasoning": "...",
  "ambiguity_signals": ["spec の上限値未指定", "UI 配置未指定", ...],
  "context_signals": ["cwd に既存 codebase あり", "team-conventions.md 検出", ...]
}
```

判定基準 (initial heuristic、 後で tuning):

| 信号 | weight |
|---|---:|
| cwd に src/ または tests/ あり | -2 (= Plan skip 寄り) |
| team-conventions.md あり | -1 |
| spec doc (spec.md / docs/) あり | -1 |
| prompt が 100 文字未満 | +1 (= Plan invoke 寄り、 曖昧) |
| prompt に 数字 / 上限 / 範囲 が含まれる | -1 (= 明確寄り) |
| prompt に「シンプル / いい感じ / お任せ」 が含まれる | +2 (= 曖昧) |
| 累計 ≥ 0 → Plan invoke | |
| 累計 < 0 → Plan skip | |

ad-hoc な閾値だが、 v3.0-alpha で実験して tune する。

### 2.2 変更: `agents/planner.md`

#### 入力契約の refine

現状:
- Goal / Constraints / Acceptance Criteria 必須、 欠ければ質問返し

v3.0:
- Goal / Constraints / AC のうち欠けているもの、 もしくは曖昧な領域 (= 上限値、 UI 配置、 色、 拡張 feature) について **必ず質問を投げる**
- 「明示なし → defensive 拒否」 default は **削除** (F1 の minimal 倒れ問題を解決)
- 代わりに「明示なし → 質問」 を default に

#### Defensive default の scope 限定 (F1 refine)

v2.1.6 の F1 を以下に refine:

- **適用領域 (引き続き defensive default)**:
  - security: 認証 / 認可漏れ、 input validation、 XSS / SQL injection
  - data integrity: trim 後空文字 / null / undefined の各 input field、 不正 JSON、 重複 entry
  - 状態不整合: join 前 send、 二重送信、 並行 update
- **適用しない領域 (= 質問 必須)**:
  - UI 拡張 feature (counter / dark mode / animation 等)
  - 表示 detail (色 / フォント / 余白 等)
  - nice-to-have feature (export / 検索 / フィルタ 等)
  - 不明確な spec の補完 (上限値、 範囲、 単位、 等)

### 2.3 変更: `agents/executor.md`

- plan.md があれば現状通り読み込む
- plan.md がない場合は user prompt + cwd context (team-conventions.md / 既存実装) を直接読んで実装
- DRY self-review (F2) は維持
- judgment traceability は plan ありなしで分岐 (なし時は「実装後の自己判断ログ」 のみ)

### 2.4 変更: `commands/pev.md`

#### flow 変更

```bash
# Step 1: 引数判定 (Linear URL / 自然文)
# Step 2: Triage 起動
TRIAGE_DECISION=$(triage_agent ...)

# Step 3: Plan (on-demand)
if [ "$TRIAGE_DECISION" = "plan_required" ]; then
  invoke planner_agent
  # Gate A (permissionMode 判定) は維持
fi

# Step 4: Execute (常時)
invoke executor_agent

# Step 5: Verify (常時)
invoke verifier_agent
```

#### flag

- `--with-plan` — Triage を skip、 必ず Plan 起動 (旧 v2.x 挙動の互換)
- `--no-plan` — Triage を skip、 必ず Plan を skip
- `--force-auto` — 維持 (Gate A skip + retry skip)
- `--strict` — 維持 (dual review)
- 新規: なし (auto judgment が default)

### 2.5 削除候補

特になし (= 既存 agent / skill は全部残す)。 ただし以下は v3.0 で意味が薄まる:

- `skills/pev-spec-template`: Plan が on-demand になり、 spec template の utility 減 (= ただし strict mode で使う)
- `skills/pev-test-design`: Plan 起動時のみ使う、 これは現状維持

## 3. v1-v4 結果との対応

| 問題 (実験で観察) | v3.0 解決 |
|---|---|
| P1 (v1 タイ): ハーネスの value 出ない | ✓ Triage で Plan skip、 overhead 削減 |
| P2 (v2 負け): text input で質問 skip | △ stream-json input 推奨は別途 doc 更新、 v3.0 では Plan 起動時の質問判定強化で対応 |
| P3 (v3 勝ち): 質問返しが機能 → user wish 引き出し | ✓ Plan agent の質問判定強化で再現性確保 |
| P4 (v4 負け): F1 minimal 倒れ | ✓ F1 scope 限定 + UI feature は質問必須 |
| P5 (効率 12-18x) | ✓ Plan on-demand で多くの task で skip、 cost 削減 |

## 4. Migration path (v2.x → v3.0)

### 互換性 / breaking changes

- **default flow が変わる**: 既存 user が `/pev <task>` で v3.0 を使うと、 多くの task で Plan skip される
- **plan.md が出ない場合がある**: artifacts/plan.md を期待する CI / hooks は要 update
- **旧挙動を保ちたい場合**: `/pev <task> --with-plan` で v2.x 互換

### Migration guide (ONBOARDING.md / README に追加)

```text
v2.x → v3.0:
- 旧 default (= 常時 PEV): `/pev <task> --with-plan` で互換
- 新 default (= on-demand Plan): `/pev <task>` のまま
- CI で plan.md を expect している場合: --with-plan を flag に追加
- audit artifact は Verify phase で常に出力されるので、 plan.md がない場合は verify.json が main 証跡
```

## 6. 不確実性 / 残課題

- **Triage agent の判定精度**: ad-hoc heuristic は v3.0-alpha で実験して tune する必要
- **質問判定 N 閾値**: 「不明確点 ≥ 何個 で質問するか」 の閾値、 default = ? (3? 5?)
- **breaking change の影響**: 既存 user (例: sample-project の dog food CI) が壊れるかもしれない
- **stream-json input の channel 問題 (F_v2_1)**: v3.0 では Plan 起動時の質問判定強化で対応するが、 text input で起動された場合の挙動は変わらない可能性
- **v1-v4 を v3.0 で再走して効果検証**: 4 つの実験データが v3.0 でどう変わるか、 dog food で実証必要
